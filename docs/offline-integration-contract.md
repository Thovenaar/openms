# Offline implementation contract

Read `coding-style.md`. These are the shared implementation-wave contracts; final behavior and retained source/runtime evidence are indexed in [offline-gameplay.md](offline-gameplay.md). All local decisions are provisional, never asserted original server rules. The integration owner controls shared `main.js`, `ingame.js`, `extract.js`, root docs/checklist and milestone validation/publication. Concurrent workers must not run builds, formatters, lint or tests while shared mutation is in flight.

## Character state

`ProfileStore.open()` asynchronously returns a store with mutable `.profile`, `.markDirty()`, `.flush()`, `.commitKeyBindings()`, `.reset()`, `.snapshot()`, `.destroy()` and explicit `.error`. Schema2 preserves the original local character, inventory/equipment, quests, location and audio settings domains and adds `keyBindings:{keys:[{type,id}],quickSlots:[keyIndex]}`:89 records and eight unique physical keys. Valid v1 migrates explicitly by adding recovered defaults; corrupt/future records never silently reset. The complete schema and transaction contract are in [offline-saves.md](offline-saves.md). Provisional bootstrap remains Maple, level1/job0, EXP/meso/fame0, HP50/MP30, STR12/DEX5/INT4/LUK4 and equipment1040002/1060002/1072001/1302000, with no starter consumables or learned skills. Gameplay mutations are synchronous; checkpoints are atomic. KeyConfig's live draft stays separate until its explicit commit succeeds.

## Fixed clock and avatar

`advanceSimulation(sim,input,ms,onStep?)` invokes optional `onStep(quantumMs)` after each executed 30-ms tick; Main uses it to update local gameplay and player artwork per tick. No second physics accumulator. Input holds `attack` and `jump` booleans alongside existing edges. Main advances ambient entities by RAF elapsed but excludes player and dynamic gameplay-owned mobs. Avatar extractor worker implements `extractAvatar(context)` in `client/tools/avatar-data.js`; context `{image,part}` existing decoder/converter. Returns `{actions,equipment}` with source-string equipment paths, keeping existing Frame schema and extending it only for evidenced transforms, consistently in renderer/validator/oracle. Starter weapon is Character/Weapon/01302000.img. Movement agent owns animation.js, stream-scene.js, physics and avatar-data.js; Main removes old avatar helpers and wires extractor after worker completion. One-shot API `setAction(name, playback='loop')`, playback `loop` or `once`; same action/mode does not restart. `.completed` becomes true at exact one-shot end; once holds last frame. Scene `updateActor(pose)` uses pose.action when supplied, else simulation.action. Combat can override action in presentation without rewriting base physics action.

## Local gameplay authority

Combat worker implements `OfflineField(scene, store, hooks)` in `offline-field.js` and supporting domain modules. `.prepare(signal)` acquires own demand-bounded mob artwork from `manifest.life`/regions using existing loaders; `.step(ms,input)` executes once per physics tick; `.snapshot()` reports local state/policy; `.destroy()` releases ownership. Main calls `.step` in onStep and reads `.action` (null or action override), `.blocksMovement`, `.dead`; hooks `{onKill(templateId),onEffect(name),onSound(category,name),onChange(),onRecover()}`. One local deterministic damage/action/AI policy, documented separately from WZ rectangles/statistics. Mobs must not remain duplicated as static region entities; worker may modify life-data.js packaging and life-system.js/life-geometry.js, but coordinate scene hooks with movement owner. Retain NPC interaction and previews without allowing inspector state to mutate gameplay. Incoming/outgoing geometry must use original explicit rectangles, not pixel bounds. No invented loot tables; available deterministic quest grants use original Act data.

## Quests

Quest worker implements `extractQuests(context)` in quest-data.js returning JSON-compatible full rule inventory and supported projections; Main assigns result to `catalog.quests`. `QuestSystem(catalog.quests,store,hooks)` exposes `.forNpc(npcId)`, `.begin(questId,npcId)`, `.complete(questId,npcId)`, `.onKill(templateId)`, `.snapshot()` and dialogue presentation descriptors. Shared state uses schema above; state 0 absent/not-started,1 active,2 completed. No repeat rewards. Unsupported conditions/actions/scripts remain classified with exact reasons; do not implement only a hardcoded quest ID. Implement complete data-supported generic conditions/dialogue choices/actions after evidence review. Hooks `{onChange(),onEffect(name)}`. Quest UI lives in quest-ui.js; mount native controls inside existing original UtilDlgEx surface via UI owner hooks. Worker returns exact integration recipe; Main integrates.

## UI and viewport

`GameUI.setProfile(store,quests)` and `setBindings(service)` connect graphical HUD/window projections and shared active input. Original HUD gauges/numbers, Item/Equip/Stat/Skill icons, keyboard/palette, quick-slot popup, cursor and chat contracts are authoritative in [ingame-ui.md](ingame-ui.md). Local messages/diagnostics do not overlay original artwork or fake chat delivery. Quest descriptors remain consumed by quest-ui.js through integration hooks. Camera helper `followCamera(camera,pose,physics,viewport)` mutates top-left coordinates using original VR bounds and small-map midpoint; viewport is `{width,height}`. Beyond800×600 the generalized half-viewport clamp is browser policy. UI remains bottom-centered in a logical800×600 plane with matching DOM/raster downscaling.
