# Browser scene contract (new interchange format, not WZ)

Generated by our Bun extractor; **not claimed to be an original file format**.

`client/public/generated/scene.json`: `{ id, source, bounds: {left,top,right,bottom}, camera: {x,y}, textures: { [id]: {url,width,height} }, entities: Entity[], evidence: string[] }`.

Texture URLs `/generated/textures/<id>.png`, straight-alpha PNG pixels decoded from original canvases. Entity: `{id,kind:'map'|'character',x,y,z,visible:true,flip:false,opacity:1,action,actions:{[name]: Frame[]}}`. Frame: `{delay:number,parts:Part[]}`; delay milliseconds. Part: `{texture:string,x:number,y:number,z:number,flip?:boolean,opacity?:number}`. Part coordinates are already top-left offsets from entity origin, including canvas origin and avatar anchors. Entity z and part z ascend back to front; ties keep input order. Extractor records which ordering rules are recovered vs still unverified. Map static entities have one action `default`, one frame. Character has real available actions such as `stand1`, `walk1`, `jump`.

Optional frame `alphaEnd` is a normalized endpoint applied to each part's starting `opacity` through original signed-integer 8-bit interpolation. Positive `delay` is required for a tween. Static one-frame character actions may have `delay:0`; multiframe actions require positive delays. Missing original endpoint assignments are carried through by extraction.

Optional entity `background:{type,rx,ry,cx,cy}` preserves original background metadata. Types 0–7 select nonrepeating/X/Y/XY and auto-scrolling modes as recovered in `client-evidence.md`. Repetition uses a persistent sprite pool. Camera displacement is relative to the manifest's initial camera; that attachment baseline is a demo decision, not an original startup-alignment claim. Snapshot exposes both wrapped `actionTimeMs` and unwrapped `elapsedMs`; background `x,y` remain logical base positions rather than transient parallax positions.

Browser loads complete scene and textures asynchronously before atomic commit; current scene remains until replacement is ready. No game-time speed dependence on display refresh; milliseconds drive animation. No WZ parsing or PNG inflation on the rendering thread.

Browser validation API `window.maple`: `ready` promise; `snapshot()` serializable state including entities (id, action, frame, visibility, position, depth, elapsed time), camera, texture count, pending loads, metrics; `pause(boolean)`; `step(ms)` deterministic advance and render; `setAction(id,action)` resets action time; `setVisible(id,bool)`; `setLayer(id,z)`; `setPosition(id,x,y)`; `setCamera(x,y)`; `reload()` async atomic asset reload. Changes render on `step(0)` when paused. Metrics retain bounded 240-sample frame/draw/loading windows and expose an approximate texture-byte count and Chrome heap where available. Failed or superseded reloads retain the previous scene; stale requests reject with `AbortError`.

Controls: action select, visibility, layer front/back, camera arrows/drag, pause/step, reload. HTML error state must show missing generated inputs rather than fictional demo content.
