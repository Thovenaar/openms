# In-game UI reconstruction

## Provenance and fidelity boundary

UI artwork and client-consumer inputs are the original `/Users/k/Development/tensorfish/Maplestory-Client` archives/executable, the lossless inventories in `docs/ingame-inventory`, and retained address-bearing decompilation/instruction/table exports. The earlier UI investigation used the isolated `/tmp/maple-ingame-ui.gpr` project; the graphical correction's selected exports are linked below. No third-party client implementation, original C/C++ source, Windows execution, or original runtime recording was supplied. The separately authorized `/Users/k/Development/tensorfish/MapleStory-Server` is **Cosmic server-reference code, not Nexon source**; its ordinary revival policy is distinguished from original client evidence in [combat](offline-combat.md#ordinary-revival-confirmation).

This preserves original raster UI artwork and address-backed HUD, window, keyboard and cursor rules while presenting durable local gameplay state. It does not claim original runtime/server parity. HP, MP, EXP, class, inventory and quests come from the shared `ProfileStore` and quest/gameplay owners, not inferred artwork values. Original character-instance formulas, scripts, remote operations and Windows reference parity remain unavailable. Browser text metrics, window arbitration and local authority are explicitly distinct from recovered artwork/coordinates.

`UI.json` currently enumerates **19 IMG entries and 110 UIWindow top-level branches**. The earlier research report's prose said 108 branches; the retained machine-readable list actually contains 110. `UI.tar.gz` preserves every inventoried node, not merely the packaged subset. The exact original IMG hashes remain in that index; `context.image` also records input hashes during normal extraction.

- `client/src/ui-layout.js`, `ui-hud.js`: original HUD gauges/numbers/controls, window/tab/menu composition and profile-driven raster projections.
- `client/src/ui-inspection.js`, `ui-icons.js`, `ui-skill-books.js`, `ui-minimap.js`: graphical inventory/equipment/stat/skill projections, demand-loaded original icons/count digits, source-derived job books and original minimap crop/markers/modes. `ProfileControls` owns sidebar-only local save/reset, validated development edits and item-offering controls. Its Revive character button opens the ordinary revival confirmation; it does not restore the field or full HP directly. The former equipment-preview/text-list window surfaces are no longer current UI.

- `client/src/camera.js`: `followCamera(camera, pose, physics, viewport)` updates top-left world coordinates from recovered VR center limits; immutable-manifest geometry is cached outside the frame loop.

`hooks` includes `{clearInput, focusGame, onError, onStatus?, playSound, onSave?, onReset?, onRecover?, onRevive?, isFieldBlocked?, onNpcDialogue?, onQuestJournal?, onOfferItem?, onChatSubmit?, isWorldInteractive?}`. `onRecover()` opens confirmation; `onRevive()` requests the ordinary atomic return-map transition. `onChatSubmit(text)` must explicitly return true to admit local speech; `isWorldInteractive(clientX,clientY)` uses the renderer's actual hit target and the life owner's live NPC admission. UI sound hooks carry only admitted original semantic cues; [exact UI/drop sound gates](ingame-audiovisual.md#runtime-integration) distinguish pointer/Space clicks from Enter and accepted carry from cancellation. Save checkpoints location/settings before flushing; reset reloads only after durable reset succeeds. Unsupported operations remain sidebar notices, not fabricated chat messages or generic DlgNotice sounds.

Additional public methods:

- `showNpc({id, templateId, name, functionName, authority, canInteract})`: requires the life owner's live `canInteract()` admission, opens original `UtilDlgEx` chrome and delegates the intact record to `hooks.onNpcDialogue(panel, npc)`. Quest begin/complete recheck that same owner for liveness, residency and modal eligibility; there is no guessed player-distance gate. World release and stationary cursor hover share the original translated, unflipped `dc` target, with each missing edge defaulted to `(-22,-65,22,0)` by the recovered loader. Unsupported imitation actors and hidden/stale artwork are not eligible. Quest rules/dialogue come only from that owner, not arbitrary String.wz speech selection or script emulation.
- `setVisible(boolean)`: inspection-only world-compositing gate; hides Pixi and DOM UI and disables input capture without discarding window state. Restoration preserves open windows. Use it only for isolated world-oracle captures; real UI acceptance keeps the UI visible.
- `activate(name)` toggles an existing or pending window; `open(name)` / `close(name)` own asynchronous demand and closure. Supported names are Item, Equip, Stat, Skill, GameMenu, ShortCut, KeyConfig, KeyConfigNotice, QuickSlotConfig, MiniMap, UtilDlgEx, Revive, GameOpt, SysOpt and Quest. MiniMap's bound action cycles an already-open window rather than closing it. `showRevival(scene)` opens Revive only for the current dead profile/scene; `confirmRevival()` shares the admitted button/automatic-confirmation path. Quest is a **native local journal mounted inside original UtilDlgEx artwork**, not a reconstruction of the unrecovered UIWindow/Quest layout. EquipmentPreview and the old standalone ToolTip gallery are removed; bounded text tooltips remain browser presentation.
- `setProfile(store, quests)` requires `ProfileStore.subscribe(listener)`, subscribes once and unsubscribes on replacement/destruction. `refreshProfile()` updates actual changes only; it is available to integration for quest changes not accompanied by store notification. There is no profile polling or text generation in `update(ms)`.
- Dialogue hooks return a cleanup function with optional `.refresh()`. The UI calls it when the dialogue changes or its window is destroyed. `panel.content` is a scrollable native rectangle `(24,30,480,116)` inside the 529×206 UtilDlgEx surface; NPC portrait mounts use left160,width344. Content ends above the original footer starting at y148; controls use y176 and do not scroll with prose. `panel.button()` returns an original-art `UIControl` with `.element`, `.setVisible(boolean)`, `.setDisabled(boolean)` and `.position(x,y)`; mount owners reuse footer controls, not allocate them on every refresh. Portrait-free journal/reset/confirmation mounts restore the full-width rectangle.
- `setBindings(service)` attaches the shared `KeyBindings` owner; subscriptions refresh keyboard and quick-slot artwork when assignments or counts change. `hooks.onOfferItem(itemId)` remains the local reactor intent boundary; the graphical inventory's double-click is recovery use, not item offering or arbitrary drop.

The UI root belongs to `app.stage` above the world, never `scene.container`; HUD gauges/art remain Pixi-rendered. Every top-level non-HUD window instead has an owned `UIRasterPlane` canvas in its DOM window, sharing the same stacking context as its native text and controls. Its existing Sprite/Container tree owns animation and geometry but is not rendered a second time by Pixi. The plane borrows already-decoded atlas ImageBitmaps through existing leases: no second decoder, texture cache, renderer or per-frame GPU readback. Unchanged artwork does not redraw. Original-UI local CSS is scoped under `.maple-ui-root` and removed by destruction; browser inspection controls remain in the sidebar.

Native controls stay attached during pointerdown; bounded DOM z-indices front complete window artwork/text together. The former rectangular DOM subtraction/clipping workaround is removed. Popup transparency and authored dimensions are preserved: ShortCut's91×244 background is not stretched or filled to its93×271 logical hit envelope. Cursor/carry have their own topmost, pointer-transparent DOM raster plane, clipped only to the actual viewport, not to a containing window. This is **browser compositor ownership**, not recovered global Windows focus arbitration. [Composition provenance](ghidra-client-corrections/composition-provenance.json) separates original popup/HUD/cursor evidence from the Canvas2D adaptation.

Graphical inventory/equipment/skill content uses original icon resources rather than a browser text list or archive gallery. Bounded browser tooltips and accessible hit labels do not establish original item-instance tooltip semantics. Lower windows reappear after native close; all icon leases remain owned by their composition layer.

## Catalog and visual bundle schema

`catalog.ui` is JSON-compatible:

```js
{
  schemaVersion: 1,
  bundles: { StatusBar: descriptor, Basic: descriptor, /* named windows */ },
  speechBubbles: { bundle: descriptor, color: -16777216 },
  minimaps: {
    "100000000": { available: true, descriptor },
    // or { available: false, reason } when the original map has no canvas
  },
  help: { Item: { title, description } },
  authority: "...",
  evidence: "docs/ingame-ui.md"
}
```

Every descriptor is the shared immutable `{url, sha256, bytes}` identity. Bundle manifests use the shared schema v1 Entity/Frame/Part contract. UI adds **no Frame extension fields**. Each original canvas is a single static entity keyed by its complete original branch path. Canvas dimensions/origins and optional normalized original delays live in `manifest.metadata.assets[path] = {id,width,height,origin,delay}`. Alias paths are retained; UOL resolution and the atlas packer preserve original pixels and shared hash identity. Canvas entities use delay `1` purely as a static storage sentinel. This is **not** an asserted original timing default.

The Basic bundle contains BtClose, BtCancel2 and the recovered compact Tab2 skin. It is owned by the HUD and borrowed by open windows. KeyConfig's actual constructor uses Basic/BtCancel2, not similarly named KeyConfig/BtCancel artwork. Inventory's type1 generic tab controller resolves `UI/Basic.img/Tab2`, not glyph-only labels or the taller Tab skin.

`catalog.ui.items` and `catalog.ui.skills` retain selected original templates, names/descriptions, properties, icon paths and immutable visual descriptors. Item properties/specification are retained for fail-closed use admission rather than inferred from names. Optional original descriptions can be absent: Seaweed2022046 has an original null description, normalized to empty optional text, not fabricated prose. Icon resources are demand-loaded through the shared visual loader.

`catalog.ui.itemLabels` retains the full original item-name table from String.wz Eqp, Consume, Ins, Etc and Cash images, keyed by numeric template ID. Extraction is bounded to150,000 name-tree nodes, depth64 and50,000 named entries, with explicit conflict/overflow errors. Names do not confer use rules or ownership. Separately packaged minimaps accept at most512 selected/closure map IDs; map images still load only when the current minimap is opened.

Each selected map's `miniMap/canvas` and scalar miniMap properties are separately packaged. Runtime retrieves only the current opened minimap and preserves original pixel scale. Authored `centerX`, `centerY`, width/height and `mag` drive the recovered signed transform `(trunc(world)+center) >> mag`, minus crop origin. The player-centered crop clamps to authored extents rather than inferring bounds from visible map geometry. Original MapHelper user/NPC/portal markers share that transform; no substitute image or marker is invented when original data is unavailable. See [minimap provenance](ghidra-client-corrections/minimap-provenance.json).

The expanded title comes from the packaged original map-name table at `quests.catalog.strings.map`, with an explicit `Map <id>` label when no name is present. Markers are original MapHelper user6×6, NPC4×7 and portal8×8 canvases: the user follows live feet coordinates; NPCs use map-wide nonhidden authored placements with original action artwork; only portal types2/7 receive a portal marker. These are not remote party positions or server-controlled NPC-presence claims. Minimized mode2 shows title-only artwork; mode1 is compact and mode0 expanded. Basic BtMax/BtMin disable at their respective endpoint modes; BtMap reports unavailable world-map routing. Browser close sits outside the native control group.
