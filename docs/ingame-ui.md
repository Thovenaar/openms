# In-game UI reconstruction

## Provenance and fidelity boundary

Implementation inputs are only the original `/Users/k/Development/tensorfish/Maplestory-Client` archives/executable, the lossless inventories in `docs/ingame-inventory`, and retained address-bearing decompilation/instruction/table exports. The earlier UI investigation used the isolated `/tmp/maple-ingame-ui.gpr` project; the graphical correction's selected exports are linked below. No third-party client, original C/C++ source, server, Windows execution, or original runtime recording was available.

This preserves original raster UI artwork and address-backed HUD, window, keyboard and cursor rules while presenting durable local gameplay state. It does not claim original runtime/server parity. HP, MP, EXP, class, inventory and quests come from the shared `ProfileStore` and quest/gameplay owners, not inferred artwork values. Original character-instance formulas, scripts, remote operations and Windows reference parity remain unavailable. Browser text metrics, window arbitration and local authority are explicitly distinct from recovered artwork/coordinates.

`UI.json` currently enumerates **19 IMG entries and 110 UIWindow top-level branches**. The earlier research report's prose said 108 branches; the retained machine-readable list actually contains 110. `UI.tar.gz` preserves every inventoried node, not merely the packaged subset. The exact original IMG hashes remain in that index; `context.image` also records input hashes during normal extraction.

## Implemented modules and integration

- `client/tools/ui-data.js`: `extractGameUI(context)`. Requires the shared extraction context and its bounded, selected `mapIds` array. Uses the existing WZ parser, `at`/`resolveNode`/`value`, original `part`, and the shared `bundle` packer. There is no UI-specific pixel decoder or network/atlas implementation.
- `client/src/game-ui.js`: `new GameUI(app, services, hooks)`, `prepare(index, signal)`, `setProfile(store, quests)`, `refreshProfile()`, `setScene(scene)`, `update(ms)`, `resize(width, height)`, `snapshot()`, `destroy()`.
- `client/src/ui-surface.js`: bounded original-raster rendering, authored state selection, accessible DOM hit planes, borrowed-resource ownership, and explicit authored-delay animation.
- `client/src/ui-layout.js`, `ui-hud.js`: original HUD gauges/numbers/controls, window/tab/menu composition and profile-driven raster projections.
- `client/src/ui-inspection.js`, `ui-icons.js`, `ui-skill-books.js`: graphical inventory/equipment/stat/skill projections, demand-loaded original icons/count digits, source-derived job books and original minimap replacement. `ProfileControls` owns sidebar-only local save/reset/recovery/class/item-offering controls. The former equipment-preview/text-list window surfaces are no longer current UI.
- `client/src/keymap.js`, `key-bindings.js`, `ui-keyconfig.js`, `ui-quickslots.js`, `ui-quickslot-config.js`: shared physical-key map, active edit draft, persistent commit and original keyboard/popup/quick-slot artwork.
- `client/src/ui-cursor.js`, `ui-chat.js`: original cursor states/hotspots and separate chat edit/log owners.
- `client/src/item-use.js`: owned-stack recovery use, shared by inventory double-click, bound keys and quick slots.
- `client/src/camera.js`: `followCamera(camera, pose, physics, viewport)` updates top-left world coordinates from recovered VR center limits; immutable-manifest geometry is cached outside the frame loop.

`hooks` includes `{clearInput, focusGame, onError, onStatus?, playSound, onSave?, onReset?, onRecover?, onNpcDialogue?, onQuestJournal?, onOfferItem?}`. Sounds remain `playSound("UI", "BtMouseOver")` and `playSound("UI", "BtMouseClick")` for actual original-control events. `onSave()` is awaited before `store.flush()` so integration can checkpoint the latest position/settings; `onReset()` is awaited after successful `store.reset()` so integration can reload the reset map. `onRecover()` queues field-authority recovery and returns its admission boolean. `onStatus` publishes unsupported operations/save notices to the sidebar, not a fake chat message. The audio owner retains its user-gesture and mute policies.

Additional public methods:

- `showNpc({id, templateId, name, functionName, authority, canInteract})`: requires the life owner's live `canInteract()` admission, opens original `UtilDlgEx` chrome and delegates the intact record to `hooks.onNpcDialogue(panel, npc)`. The quest owner rechecks the same function before begin/complete because proximity/liveness can change while dialogue is open. Quest rules/dialogue come only from that owner; this is not arbitrary String.wz speech selection or script emulation.
- `setVisible(boolean)`: inspection-only world-compositing gate; hides Pixi and DOM UI and disables input capture without discarding window state. Restoration preserves open windows. Use it only for isolated world-oracle captures; real UI acceptance keeps the UI visible.
- `open(name)` / `close(name)`: asynchronous window demand and local close. Supported names are Item, Equip, Stat, Skill, GameMenu, ShortCut, KeyConfig, QuickSlotConfig, MiniMap, UtilDlgEx, GameOpt, SysOpt and Quest. Quest is a **native local journal mounted inside original UtilDlgEx artwork**, not a reconstruction of the unrecovered UIWindow/Quest layout. EquipmentPreview and the old standalone ToolTip gallery are removed; bounded text tooltips remain browser presentation.
- `setProfile(store, quests)` requires `ProfileStore.subscribe(listener)`, subscribes once and unsubscribes on replacement/destruction. `refreshProfile()` updates actual changes only; it is available to integration for quest changes not accompanied by store notification. There is no profile polling or text generation in `update(ms)`.
- Dialogue hooks return a cleanup function with optional `.refresh()`. The UI calls it when the dialogue changes or its window is destroyed. `panel.content` is a scrollable native rectangle `(24,30,480,132)` inside the 529×206 UtilDlgEx surface; footer controls use y176. `panel.button()` returns an original-art `UIControl` with `.element`, `.setVisible(boolean)`, `.setDisabled(boolean)` and `.position(x,y)`; mount owners reuse footer controls, not allocate them on every refresh.
- `setBindings(service)` attaches the shared `KeyBindings` owner; subscriptions refresh keyboard and quick-slot artwork when assignments or counts change. `hooks.onOfferItem(itemId)` remains the local reactor intent boundary; the graphical inventory's double-click is recovery use, not item offering or arbitrary drop.

The UI root belongs to `app.stage` above the world, never `scene.container`. Its owned DOM overlay is attached alongside the canvas. Original-UI local CSS is scoped under `.maple-ui-root` and removed by destruction. Browser audio/effect/life inspection controls instead flow inside the existing scrollable sidebar; they never overlay the WebGL viewport.

Native controls stay attached during pointerdown; bounded DOM z-indices follow the Pixi window order. Lower DOM captions/controls are clipped against the higher windows' rectangular envelopes, including alternate-skin extents, so they cannot bleed above higher raster artwork. Rectangle subtraction handles overlapping occluders rather than an XOR mask. The bounded four-window geometry is refreshed on stack, drag, resize and detail changes, not in the animation loop. This is explicit **browser window-occlusion policy**, not recovered original alpha-hit or global focus arbitration.

Graphical inventory/equipment/skill content uses original icon resources rather than a browser text list or archive gallery. Bounded browser tooltips and accessible hit labels do not establish original item-instance tooltip semantics. Lower windows reappear after native close; all icon leases remain owned by their composition layer.

## Catalog and visual bundle schema

`catalog.ui` is JSON-compatible:

```js
{
  schemaVersion: 1,
  bundles: { StatusBar: descriptor, Basic: descriptor, /* named windows */ },
  minimaps: {
    "100000000": { available: true, descriptor },
    // or { available: false, reason } when the original map has no canvas
  },
  help: { Item: { title, description } },
  authority: "...",
  evidence: "docs/ingame-ui.md"
}
```

Every descriptor is the shared immutable `{url, sha256, bytes}` identity. Bundle manifests use the shared schema v1 Entity/Frame/Part contract. UI adds **no Frame extension fields**. Each original canvas is a single static entity keyed by its complete original branch path. Canvas dimensions/origins and optional normalized original delays live in `manifest.metadata.assets[path] = {id,width,height,origin,delay}`. Alias paths are retained; UOL resolution and the atlas packer preserve original pixels and shared hash identity. Canvas entities use delay `1` purely as a static storage sentinel. This is **not** an asserted original timing default.

The Basic bundle contains BtClose, BtCancel2 and the recovered compact Tab2 skin. It is owned by the HUD and borrowed by open windows. KeyConfig's actual constructor uses Basic/BtCancel2, not similarly named KeyConfig/BtCancel artwork. Inventory's type1 generic tab controller resolves `UI/Basic.img/Tab2`, not glyph-only labels or the taller Tab skin.

`catalog.ui.items` and `catalog.ui.skills` retain selected original templates, names/descriptions, properties, icon paths and immutable visual descriptors. Item properties/specification are retained for fail-closed use admission rather than inferred from names. Optional original descriptions can be absent: Seaweed2022046 has an original null description, normalized to empty optional text, not fabricated prose. Icon resources are demand-loaded through the shared visual loader.

`catalog.ui.itemLabels` retains the full original item-name table from String.wz Eqp, Consume, Ins, Etc and Cash images, keyed by numeric template ID. Extraction is bounded to150,000 name-tree nodes, depth64 and50,000 named entries, with explicit conflict/overflow errors. Names do not confer use rules or ownership. Separately packaged minimaps accept at most512 selected/closure map IDs; map images still load only when the current minimap is opened.

Each selected map's `miniMap/canvas` and scalar miniMap properties are separately packaged. Runtime retrieves only the current opened minimap. Authored `centerX`, `centerY`, width/height/magnification properties, when present, remain metadata; no guessed player-marker transformation is applied.

## Browser policies, resource bounds and timing

- Four simultaneously open windows, at most1536 raster objects and128 controls per surface, at most128 explicit frames per control state. UI extraction traversals are bounded to16,000 nodes and depth64 per artwork branch. Inventory accepts the store's4096 stacks; an icon composition holds at most96 visible icons with four concurrent loads. Overflow fails explicitly, never silently truncates.
- HUD, Basic and Cursor are startup UI resources. Window art, item/skill icons and per-map minimaps are demand-loaded through `loadVisualBundle`; there is no second atlas/network path or decoded-image cache. AtlasStore owns decode/upload budgets and shared residency.
- Windows destroy DOM listeners and Pixi consumers before their resource owner. Minimap replacement destroys its previous sprite before releasing its lease. Stale/cancelled loads cannot attach to closed windows. Failed minimap replacement retains its last complete image and reports failure. Catalog refresh prepares a complete new HUD/Basic owner before replacing the existing UI; failure preserves the old UI.
- UI raster order follows explicit composition, not original asset-tree enumeration. All per-surface raster nodes use equal z so background skins cannot obscure later controls/glyphs. Window fronting updates bounded CSS z-indices without detaching DOM nodes during pointerdown; this preserves actual native click/focus. Expanded inventory updates raster/DOM controls and its drag strip together.
- Reference-plane scaling, initial centering, drag strips, browser text (`11px Tahoma, Arial`), tooltip layout, modal focus trapping, four-window policy and unknown skin placements are browser policies. Windows are restricted to800×515, above the complete HUD/button extent, and use the same initial/drag clamps; expanded inventory updates content and control extents together. Tooltips use measured bounds inside800×600. The earlier [expanded-inventory clamp replay](offline-validation/main/clamp-after.json) is historical evidence, not acceptance of the current graphical window. Tahoma is original string ID8, not proof of browser font metrics.
- Physical defaults come from `keymap.js`, not old help captions: **Alt Jump, Control Attack, I Item, E Equip, S Stat, K Skill, C KeyConfig, H MiniMap, Q Quest, ] QuickSlot**. Arrows remain directional; Down plus the currently bound Jump requests eligible drop-through; Up enters supported portals. Space is Talk, X Sit, Z Pickup and M an unsupported original action, not Space-jump/X-attack/M-minimap aliases. F10 is unassigned by default. Unsupported actions report their boundary instead of pretending to execute.
- KeyConfig is **nonmodal**: its active draft drives live input and quick slots while editing. UtilDlgEx confirmations/dialogue and QuickSlotConfig are modal boundaries. Native text/select focus captures typing and clears gameplay input; modal Tab arbitration remains browser policy. Authored disabled controls remain focusable for explanations but do not dispatch actions.
- Nonmodal window hotkeys still toggle while native buttons have focus. Escape closes the top window (KeyConfig may ask to discard changes), then chat, or opens GameMenu when neither applies. Enter opens chat from canvas focus; a focused native button keeps its own Enter activation instead. Bound recovery-item presses do not clear unrelated held movement. Blur/visibility changes clear held input/drag state. Earlier [hotkey](offline-validation/main/hotkey-after.json) and [recovery](offline-validation/main/recovery-reactor-after.json) captures predate this input correction.
- Explicit authored numeric or numeric-string delays are normalized to finite positive milliseconds. Only fully timed authored state sequences advance. Missing timing stays static and is reported as unsupported; the generic renderer's 120ms default is not cited as UI evidence. The generic 120ms original loader chain recovered by the portal domain has not yet been connected to every UI consumer here.

### Key draft, quick slots, chat and cursor

The shared map contains89 packed `{type,id}` records and eight unique assignable physical-key indices. Right Control/Alt/Shift normalize to their left records; numpad digits normalize to number-row records. Default quick slots are Shift, Insert, Home, PageUp, Control, Delete, End and PageDown. These are keys, not eight independent action bindings.

Opening KeyConfig clones committed bindings into an **active draft**. Dragging a palette action, existing assignment or owned eligible item replaces the destination and clears duplicate sources; dropping an existing key back in the palette removes it. Delete clears assignments; Default restores the recovered map and quick keys, both after confirmation. Draft changes are live but do not enter ordinary profile checkpoints. OK commits through the profile store before closing; Cancel/close restores the committed map, asking to discard changed drafts. A failed commit reports failure and keeps the editor/draft available.

The quick-key popup edits the parent's draft. Its eight capture boxes use `(65+35*column,113+34*row)`; Tab switches between the grid and footer focus groups, arrows navigate within the selected group, and a valid physical key replaces only the selected slot without auto-advancing. Duplicate/unassignable keys are rejected. Enter accepts into the parent draft; Escape first clears capture/footer focus, then closes/cancels when unfocused. Popup Cancel reverses its changes; popup OK alone does **not** persist the parent draft. The HUD displays original action/item icons, legends and current item counts; clicking activates the mapped key, and drag assignment requires KeyConfig open. Its current `(647,427)` origin and local two-by-four grid are implemented presentation, not a completed native absolute-transform proof.

Ordinary recovery use requires an owned positive stack, a living/unblocked profile and at least200ms since the previous accepted use. The same gate handles double-click, bound key and quick-slot click. Supported original flat/percent HP/MP effects clamp to maxima and atomically decrement one item, removing an exhausted stack, then request a checkpoint. **Full HP/MP does not reject consumption.** Unknown effects/restrictions and unsupported categories fail closed; bindability is not proof of local use support. There are no fabricated server packets, starter potions or loot grants. See [save contract](offline-saves.md).

Chat separates log and edit state: Enter from canvas focus opens editing; empty Enter closes; Escape clears/closes; empty left/right exits; Up/Down recalls bounded64-entry history while preserving the current draft. Native focused buttons retain their Enter activation. Text is capped at255 characters and IME composition is not submitted early. Minimize/expand and13-pixel resize steps are implemented; the browser selector retains original channel labels but cannot join/send to a server. Submit clears the input and reports **not sent** in the sidebar. It never echoes unsent text into the game chat log.

Cursor resources preserve WZ origins as hotspots; no guessed top-left offset or CSS cursor substitutes them inside the viewport. An owned canvas class/style suppresses the native pointer and is removed on destruction, independently of other canvas inline styles. States0–12 are loaded with authored timing. State−1 restores the remembered state, updated only when the previous state is below9. Press maps7→9,8→10 and other states→12; release restores9/10/12. Binding drag uses11 plus the original icon ghost; cancellation clears it. Only exercised browser behavior can establish interaction correctness; original Windows timing/focus parity remains unverified.

`resize(width,height)` retains `scale=min(1,width/800,height/600)`, horizontal centering and bottom anchoring. The Pixi root and DOM overlay share that logical transform. DOM placement measures both canvas axes relative to its parent, including nonuniform CSS scale; dragging converts X/Y through their separate committed screen scales. ResizeObserver plus bounded ancestor mutation/window resize/scroll observation schedules layout commits outside RAF gameplay updates. `snapshot().layoutGeneration` advances after a committed layout, allowing input automation to wait for actual transforms. Rotated/skewed CSS embedding is not claimed supported.

`followCamera(camera, pose, manifest.physics, {width,height})` mutates and returns the same top-left camera object. Do **not** pass the simulation's physical `bounds`. Original `00641ef1` stores centers in `[VRLeft+400, VRRight-400]` and `[VRTop+300, VRBottom-300]` at800×600; equal/reversed intervals collapse to their signed-integer midpoint (`Math.trunc`). The source fallback offsets are left−20, top−60, right+20 and bottom+100. Mapping the source geometry globals to foothold extrema is the explicitly provisional interpretation, cached once per immutable physics manifest. Explicit VR zero values are retained; `VRLimit` is not a camera gate. Other viewport sizes generalize the half-viewport values without stretching world pixels, a browser extension rather than a recovered original-resolution mode. Empty geometry is usable only when all four VR values exist; nonfinite/unbounded metadata fails visibly.
